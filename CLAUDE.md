# CLAUDE.md — AleksSamArt

## Що це за проєкт

Сайт-портфоліо художника (AleksSamArt): вітрина робіт із можливістю **замовити картину** або **купити вже готову**. Без бази даних, на безкоштовному хостингу **Netlify**. Усі зображення зберігаються у **Google Drive** (публічна папка) і вантажаться на льоту напряму з Drive; список робіт віддає Netlify Function.

## Мови сайту

Сайт мультимовний (тексту небагато, тому реалізується простими словниками перекладів):

- **Українська (основна, за замовчуванням)**
- Англійська, німецька, французька, іспанська, італійська, норвезька, польська, шведська, чеська

Локалі: `uk` (default), `en`, `de`, `fr`, `es`, `it`, `no`, `pl`, `sv`, `cs`.

## Технічний стек

| Шар | Технологія | Чому |
|---|---|---|
| Генератор | **Astro** (SSG) | Статичний вивід = швидко на free-хостингу, гарне SEO |
| Анімації | **GSAP + ScrollTrigger** | Плавні ефекти «стосу карток», паралакс, повноекранний скрол |
| Backend | **Netlify Functions** (serverless) | Тримає Google API-секрети поза клієнтом, runtime-доступ до Drive |
| Форми | **Netlify Forms** | Безкоштовна обробка замовлень (100 форм/міс у free) |
| Хостинг | **Netlify (free)** | Деплой з git, безкоштовно |

JS на клієнті — лише там, де потрібно (анімації, лайтбокс, форма). Решта — статичний HTML.

## Архітектура та потік даних

```
Браузер (клієнт)
   │  ① GET / → статичний HTML (збірка Astro)
   │  ② запит до Netlify Function → список робіт + посилання на зображення
   ▼
Netlify Functions (Google Drive API, секрети тут)
   │  OAuth (refresh token із env)
   ▼
Google Drive (папки робіт)
```

- **На етапі build** список робіт підтягується з Drive і вшивається в статичний HTML (SEO + швидкий перший екран). Самі зображення при build не скачуються.
- **При завантаженні сторінки** клієнт запитує Netlify Function, яка повертає **актуальний** список робіт із посиланнями на зображення (runtime-оновлення статики).
- **Зображення публічні** («Anyone with the link») — браузер вантажить їх напряму з Drive; функція тільки повертає список.
- Зміни в Drive видно на сайті **без редеплою**.
- Секрети Google — **тільки** в Netlify env, ніколи не в клієнтський код.

## Структура зображень у Google Drive

**Папка на роботу.** У кореневій папці Drive кожна робота — окрема папка. Усередині — головне фото + додаткові (етапи, ракурси):

```
<коренева папка Drive>/
├── <назва роботи 1>/
│   ├── 00-main.jpg          # головне фото — показується на екрані
│   ├── 01-stage-1.jpg       # етапи роботи
│   ├── 01-stage-2.jpg
│   └── 02-angle-1.jpg       # ракурси
└── <назва роботи 2>/
    └── 00-main.jpg
    └── ...
```

Конвенції:
- **Порядок робіт у скролі = порядок папок у корені**.
- Файл із префіксом `00-` — головне зображення роботи (те, що «лежить на стосі»).
- Решта файлів (`01-`, `02-`, …) — додаткові фото (етапи, ракурси), показуються в лайтбоксі.
- Префікси забезпечують стабільне сортування всередині папки.
- **Назва роботи = назва папки** (не перекладається). Інших метаданих (рік, техніка, розмір оригіналу) поки немає — додати пізніше.
- **Проданий твір** — префікс `SOLD-` у назві папки (`SOLD-Назва`): функція виключає такі роботи зі стосу.
- **Уся папка робіт у Drive публічна** («Anyone with the link can view»).

## Env-змінні (Netlify)

| Змінна | Призначення |
|---|---|
| `GOOGLE_CLIENT_ID` | Google OAuth client ID (вводить користувач) |
| `GOOGLE_CLIENT_SECRET` | Google OAuth client secret (вводить користувач) |
| `GOOGLE_REFRESH_TOKEN` | Створюється автоматично скриптом `setup:google` |
| `GOOGLE_DRIVE_FOLDER_ID` | ID кореневої папки з роботами |
| `CONTACT_EMAIL` | Email, на який приходять замовлення (Netlify Forms) |
| `FACEBOOK_URL` | Посилання на Facebook |
| `INSTAGRAM_URL` | Посилання на Instagram |
| `CURRENCY` | Валюта цін. Дефолт — `USD` (умовні одиниці). Змінюється в один момент |

**Google-доступ.** Для запуску достатньо додати `GOOGLE_CLIENT_ID` і `GOOGLE_CLIENT_SECRET` у `.env`, після чого **один раз** запустити `npm run setup:google`: скрипт відкриває екран підтвердження Google і сам дописує `GOOGLE_REFRESH_TOKEN` у `.env`. Цей токен копіюється в Netlify env (Dashboard або `netlify env:set`). Секрети — ніколи не в клієнтський код і не в git.

⚠️ OAuth-додаток у Google Cloud Console має бути у статусі **Production** (не Testing) — інакше refresh token протухає кожні 7 днів.

## Візуальний дизайн та UX

- **Повноекранний вертикальний скрол**: 1 екран = 1 робота. Скрол вниз → наступний екран з наступною роботою.
- Кожне зображення виглядає як **картка, що лежить на стосі** інших (нахил, тінь, перспектива — реалізується GSAP).
- **Клік на зображення** → відкривається режим перегляду (лайтбокс) з усіма фото роботи: етапи роботи, ракурси.
- **Боковий скролінг-індикатор**: праворуч вертикальні точки, одна на роботу, що відповідає позиції в скролі; активна точка підсвічена, клік по точці = перехід до роботи.
- **Контакти** — внизу **кожного екрана**: іконки-посилання Facebook та Instagram (персистентний футер поверх повноекранних екранів).
- **Кнопки «Замовити» / «Купити»** — на кожному екрані роботи; «Купити» лише для робіт із ціною в `src/config`. Обидві відкривають модальну форму.

## Замовлення та купівля

Два окремі потоки:

**«Замовити»** (індивідуальна робота) → модальне вікно:
- Поле вибору **розміру** з фіксованого списку. Тимчасові дефолти (поки користувач не надасть остаточний список): **A2 = 300, A3 = 200, A4 = 100** у.о.
- Після вибору розміру **ціна підставляється автоматично**.
- Розміри/ціни — у конфігу проєкту (`src/config`), **не в БД**.

**«Купити»** (готова робота) → те саме модальне вікно, але з **фіксованою ціною за твір**:
- Ціна готової роботи — мапа «назва папки → ціна» у `src/config`.
- «Готова до купівлі» робота = та, для якої є ціна в мапі; решта — лише «Замовити».
- Поле розміру не потрібне.

Спільне:
- **Назва поточної роботи підставляється у форму автоматично**.
- Поля форми (мінімум): **ім'я, email**, розмір (для «Замовити»), **коментар**.
- Надсилання — через **Netlify Forms**, замовлення приходить на `CONTACT_EMAIL` художника.
- Після відправки — підтвердження успіху (спасибі).
- Розмітка форми — у статичному HTML (Netlify виявляє форми на build).

## Інтернаціоналізація

- Локалізація через Astro i18n: окремі маршрути на локалі (`/en/`, `/de/`, …).
- **Дефолтна локаль `uk` — на корені `/`** (без префікса). Решта локалей — з префіксом: `/en/`, `/de/`, тощо.
- **Назви робіт не перекладаються** — беруться з назв папок Google Drive.
- Переклади — у словниках `src/i18n/`, не в розмітці.
- Автовибір мови відвідувача за `Accept-Language` з фолбеком на `uk`.

```
src/
├── components/      # секції, картки робіт, лайтбокс, форма

```

## Команди

- `npm install` — встановити залежності
- `npm run setup:google` — отримати refresh token Google (один раз, після додавання `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET` у `.env`)
- `npm run dev` — локальний dev-сервер
- `npm run build` — збірка статики
- `npm run preview` — перегляд збірки локально
- Деплой на Netlify: push у підключене репозиторій або `netlify deploy`

## Розгортання (Netlify free)

- Build command: `npm run build`, publish directory: `dist`.
- Env-змінні — у Netlify Dashboard (або через `netlify.toml`).
- Functions у Netlify знаходяться автоматично; перевірити шлях виявлення для Astro.

## Ключові рішення (рішення по проєкту)

1. **Astro + GSAP** — баланс швидкості, SEO та анімацій для дизайну «стос карток».
2. **Netlify Functions (runtime)** — секрети Google тримаються серверно; список робіт оновлюється без редеплою.
3. **Netlify Forms** — безкоштовна обробка замовлень без сервера.
4. **Папка на роботу** в Google Drive — проста логіка читання та підтримка художником.
5. **Фіксовані розміри + ціна** — прозоро для покупця; конфіг без БД. Дефолти A2/A3/A4 — тимчасові.
6. **Іконки-посилання** Facebook/Instagram у футері кожного екрана.
7. **Дефолтна локаль `uk` без префікса** в URL — краща UX; решта локалей з префіксом.
8. **Валюта** — ціни завжди з символом валюти; дефолт `USD` (умовні одиниці), змінюється через `CURRENCY`.
9. **Назви робіт не перекладаються** — з назв папок Google Drive.
10. **SEO-гібрид** — статичний HTML із роботами на build + runtime-оновлення через функцію.
11. **Зображення публічні** — вантажаться напряму з Drive; функція не проксіює байти.
12. **OAuth + setup-скрипт** — користувач вводить лише `GOOGLE_CLIENT_ID`/`GOOGLE_CLIENT_SECRET`; refresh token генерується автоматично.
13. **Два потоки продажів** — «Замовити» (розмір → ціна) і «Купити» (фіксована ціна за твір).
14. **Проданий твір = префікс `SOLD-`** у назві папки — без додаткових файлів у Drive.

## Відкриті питання

- Конкретний список розмірів і цін — користувач надасть пізніше, після реалізації.
- Поведінка проданих робіт: приховати зі стосу (дефолт) чи показувати з бейджем «Продано».
- Метадані робіт (рік, техніка, розмір оригіналу) — зараз лише назва; формат додати пізніше.
- Перевести OAuth-додаток у Google Console у статус **Production** — кроки на етапі налаштування.
- Git-репозиторій буде створений вкінці проєкту — не займатися цим поки що.
