# CLAUDE.md — AleksSamArt

## Що це за проєкт

Сайт-портфоліо художника (AleksSamArt): вітрина робіт із можливістю **замовити картину** або **купити вже готову**. Без бази даних, на безкоштовному хостингу **Netlify**. Зображення робіт лежать **у самому проєкті** (папки в `src/assets/works/`) і оптимізуються на build через `astro:assets`.

## Мови сайту

Сайт мультимовний (тексту небагато, тому реалізується простими словниками перекладів):

- **Українська (основна, за замовчуванням)**
- Англійська, німецька, французька, іспанська, італійська, норвезька, польська, шведська, чеська

Локалі: `uk` (default), `en`, `de`, `fr`, `es`, `it`, `no`, `pl`, `sv`, `cs`.

## Технічний стек

| Шар | Технологія | Чому |
|---|---|---|
| Генератор | **Astro** (SSG) | Статичний вивід = швидко на free-хостингу, гарне SEO |
| Анімації | **GSAP + ScrollTrigger** | Плавні ефекти «стосу карток», паралакс, повноекранний скрол |
| Зображення | **astro:assets** (вбудована оптимізація) | WebP до 2048px на build — статика з `src/assets/works/` |
| Форми | **Netlify Forms** | Безкоштовна обробка замовлень (на free — безлімітно) |
| Хостинг | **Netlify (free)** | Деплой з git, безкоштовно |

JS на клієнті — лише там, де потрібно (анімації, лайтбокс, форма). Решта — статичний HTML.

## Архітектура та потік даних

```
Браузер (клієнт)
   │  GET / → статичний HTML (збірка Astro)
   ▼
Netlify (free) — статичні файли з CDN
   │  зображення — оптимізовані на build, з `src/assets/works/`
```

- **На build** список робіт сканується з папок `src/assets/works/` і вшивається в статичний HTML (SEO + швидкий перший екран). Зображення оптимізуються (`astro:assets`): WebP, до 2048px.
- **Клієнт отримує готовий HTML** — без runtime-запитів; зображення роздає CDN Netlify напряму.
- **Щоб оновити роботи** — додати/змінити папки в `src/assets/works/` і задеплоїти (новий коміт).

## Структура зображень у проєкті

**Папка на роботу.** У `src/assets/works/` кожна робота — окрема папка. Усередині — головне фото + додаткові (етапи, ракурси):

```
src/assets/works/
├── <назва роботи 1>/
│   ├── <name>-1.jpg         # головне фото — «зображення з номером 1»
│   ├── <name>-2.jpg         # етапи роботи
│   └── <name>-3.jpg         # ракурси
└── <назва роботи 2>/
    └── <name>-1.jpg
    └── ...
```

Конвенції:
- **Головне фото** — файл із числом `1` у кінці назви (`*-1.*`); якщо такого немає — перше зображення за сортуванням.
- Решта зображень папки — додаткові фото (етапи, ракурси), показуються в лайтбоксі.
- **Порядок робіт у скролі** = порядок додавання: перша додана — вгорі, кожна наступна — нижче. Задається списком `WORKS_ORDER` у `src/config/works-order.ts` (нова робота дописується в кінець списку). Папки називаються просто ім'ям роботи, без префіксів.
- **Назва роботи = назва папки** (не перекладається). Інших метаданих (рік, техніка, розмір оригіналу) поки немає — додати пізніше.
- **Проданий твір** — префікс `SOLD-` у назві папки (`SOLD-Назва`): така робота виключається зі стосу.
- **Замовлення** (робота клієнта) — префікс `ORDER-` у назві папки (`ORDER-Назва`): робота лишається в стосі, на картці з'являється бейдж «Замовлення» (перекладається на 10 мов), а префікс прибирається з назви.
- Зображення оптимізуються на build (`astro:assets`): WebP, до 2048px.

## Env-змінні (Netlify)

| Змінна | Призначення |
|---|---|
| `CONTACT_EMAIL` | ⚠️ Не керує доставкою замовлень — зарезервований на майбутнє (напр., mailto). Пошту отримувача задають у Dashboard → Forms → Form notifications |
| `FACEBOOK_URL` | Посилання на Facebook |
| `INSTAGRAM_URL` | Посилання на Instagram |
| `CURRENCY` | Валюта цін. Дефолт — `USD` (умовні одиниці). Змінюється в один момент |

## Візуальний дизайн та UX

- **Повноекранний вертикальний скрол**: 1 екран = 1 робота. Скрол вниз → наступний екран з наступною роботою.
- Кожне зображення виглядає як **картка, що лежить на стосі** інших (нахил, тінь, перспектива — реалізується GSAP).
- **Клік на зображення** → відкривається режим перегляду (лайтбокс) з усіма фото роботи: етапи роботи, ракурси.
- **Боковий скролінг-індикатор**: праворуч вертикальні точки, одна на роботу, що відповідає позиції в скролі; активна точка підсвічена, клік по точці = перехід до роботи.
- **Контакти** — внизу **кожного екрана**: іконки-посилання Facebook та Instagram (персистентний футер поверх повноекранних екранів).
- **Кнопки «Замовити» / «Купити»** — на кожному екрані роботи; «Купити» — на всіх роботах, крім замовлень. Обидві відкривають модальну форму.

## Замовлення та купівля

Два окремі потоки:

**«Замовити»** (індивідуальна робота) → модальне вікно:
- Поле вибору **розміру** з фіксованого списку. Тимчасові дефолти (поки користувач не надасть остаточний список): **A2 = 300, A3 = 200, A4 = 100** у.о.
- Після вибору розміру **ціна підставляється автоматично**.
- Розміри/ціни — у конфігу проєкту (`src/config`), **не в БД**.

**«Купити»** (готова робота) → те саме модальне вікно, але з **фіксованою ціною за твір**:
- Кнопка «Купити» — на **кожній** роботі, що не є замовленням (немає префікса `ORDER-`).
- Ціна — константа `PORTRAIT_PRICE` (400 у.о.) у `src/config/site.ts`.
- Поле розміру не потрібне.
- (Плановано) індивідуальні ціни готових робіт — мапа `ARTWORK_PRICES` «назва папки → ціна»; поки порожня.

Спільне:
- **Назва поточної роботи підставляється у форму автоматично**.
- Поля форми (мінімум): **ім'я, email**, розмір (для «Замовити»), **коментар**.
- Надсилання — через **Netlify Forms**: Netlify зберігає замовлення в Dashboard (Forms → «order» → Submissions). **Email-сповіщення** налаштовуються окремо: Dashboard → Forms → «order» → **Form notifications** → Email notification (пошта отримувача задається там, **не** через `CONTACT_EMAIL`).
- Після відправки — підтвердження успіху (спасибі).
- Розмітка форми — у статичному HTML (Netlify виявляє форми на build).

## Інтернаціоналізація

- Локалізація через Astro i18n: окремі маршрути на локалі (`/en/`, `/de/`, …).
- **Дефолтна локаль `uk` — на корені `/`** (без префікса). Решта локалей — з префіксом: `/en/`, `/de/`, тощо.
- **Назви робіт не перекладаються** — беруться з назв папок робіт.
- Переклади — у словниках `src/i18n/`, не в розмітці.
- Автовибір мови відвідувача за `Accept-Language` з фолбеком на `uk`.

```

├── components/      # секції, картки робіт, лайтбокс, форма

netlify.toml         # деплой, env, redirects
.env                 # локальні секрети (у .gitignore)
```

## Команди

- `npm install` — встановити залежності
- `npm run dev` — локальний dev-сервер

- Деплой на Netlify: push у підключене репозиторій або `netlify deploy`

## Розгортання (Netlify free)

- Build command: `npm run build`, publish directory: `dist`.

## Ключові рішення (рішення по проєкту)

1. **Astro + GSAP** — баланс швидкості, SEO та анімацій для дизайну «стос карток».
2. **Зображення в проєкті (не Google Drive)** — ~100 фото невеликі; без OAuth/функцій/секретів, роздаються з CDN Netlify швидше за Drive.
3. **Netlify Forms** — безкоштовна обробка замовлень без сервера.
4. **Папка на роботу** в `src/assets/works/` — проста логіка читання та підтримка художником.
5. **Оптимізація на build (`astro:assets`)** — WebP до 2048px: мала вага сторінок і трафік.
6. **Фіксовані розміри + ціна** — прозоро для покупця; конфіг без БД. Дефолти A2/A3/A4 — тимчасові.
7. **Іконки-посилання** Facebook/Instagram у футері кожного екрана.
8. **Дефолтна локаль `uk` без префікса** в URL — краща UX; решта локалей з префіксом.
9. **Валюта** — ціни завжди з символом валюти; дефолт `USD` (умовні одиниці), змінюється через `CURRENCY`.
10. **Назви робіт не перекладаються** — з назв папок робіт.
11. **Статичний SEO** — роботи вшиваються в HTML на build; оновлення = новий коміт і редеплой.
12. **Два потоки продажів** — «Замовити» (розмір → ціна) і «Купити» (фіксована ціна за твір).
13. **Проданий твір = префікс `SOLD-`** у назві папки — без додаткових файлів.
14. **Замовлення (робота клієнта) = префікс `ORDER-`** у назві папки: унікальний підпис після префікса — назва роботи, бейдж «Замовлення» — перекладений.

## Відкриті питання

- Конкретний список розмірів і цін — користувач надасть пізніше, після реалізації.
- Поведінка проданих робіт: приховати зі стосу (дефолт) чи показувати з бейджем «Продано».
- Метадані робіт (рік, техніка, розмір оригіналу) — зараз лише назва; формат додати пізніше.
- `astro check` не встановлено (`@astrojs/check`) — додати на етапі 6, разом із SEO/hreflang/sitemap.
